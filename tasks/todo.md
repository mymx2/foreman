# Todo

一次性待办清单，不被 git 追踪。存放位置：

```
tasks/__<sub>/YYYYMMDD/NN-todo-<kebab-slug>.md
```

- `YYYYMMDD` — 创建当日日期
- `NN` — 当天序号（01、02…），plan 与对应 todo 共享同一序号
- `<kebab-slug>` — 小写英文短横线格式，概括需求的简短标识

示例：`tasks/__example-app/20260115/01-todo-add-dark-mode.md`

## 进度元信息

文件头部必须携带 frontmatter，供不读正文即可判断进度：

```markdown
---
status: in-progress | done | abandoned
---
```

流转：`in-progress` → `done` / `abandoned`。创建时设置，状态变化时更新。

## 条目要求

条目 = 可独立勾销的最小工作单元，一条写完能被打断后接上。每条说明改动对象和完成判据（文件、命令或手测路径）；会改动数据、配置或删除内容的条目加一句回滚方式。

## 完成时沉淀

勾掉条目时留下执行痕迹，跨会话可接续：

- **验证结果**：跑过的验收命令及其结果（通过/跳过及原因）
- **决策与偏差**：实现中偏离计划的地方、临时决策及理由
- **遗留风险**：未覆盖的场景、后续需要跟进的事项

小改动一行备注即可；大型改造（多条目、跨天）按条目分小节沉淀，供对应 audit 或后续任务引用。
