# AI 视觉设计决策层

AI 视觉生成的通用方法论。核心信念：**一致性靠参考图锚定，不靠文字描述；先确认锚点再批量派生，否则批量返工。**

## Outcome Contract

- **Outcome**: 产出一批符合需求、规格统一、主体/风格一致的 AI 生成视觉资产（图/视频/品牌物料），并完成交付质量门。
- **Done when**: 意图识别正确（场景没判错）；生成前确认已做（产出什么、规格、用到的素材写清）；每件产物从结果读真实引用；系列产物锚点链成立；逐件与成套检查结论写给用户。
- **Evidence**: 生成前确认消息；逐件/成套检查结论；锚点产物 + 锚点描述两件套。
- **Authorization**: 每次发起生成前必须先经用户确认；重做工件、推进下一批、改规格都要重新确认。绝不伪造检查或产物；没生成就不能说已生成。

## 工作流总览（标准五步）

1. **意图识别**：先定领域（静态图 / 品牌 / 视频），再定具体场景，两步都互斥单选。判错代价最高——场景产出规模差 5 倍时先问。
2. **定参数 + 生成前确认**：见 `references/core-protocol.md`。
3. **发起生成**：有参考素材绝不降级成纯文字生成（一致性在这一步丢）。
4. **每件产物立刻记录真实引用**：用语义角色名绑定，不预判路径。
5. **整批收尾**：逐件检查 + 成套检查 + 把结论写给用户。不合格不自动重做（重做要花钱），由用户决定。

## 通用底线（任何场景都适用）

- **参考图是硬约束，不是建议。** 收到的参考图全部带进，不静默丢弃/抽样/去重；超上限时告知上限、保留前 N 张或问留哪些；多图各有用途时在提示词里写明每张的角色。
- **绝不把规格画进画面。** 色值代码、字体名、字段标签词（"标题""副标题"）、结构说明、提示词片段，一个都不能出现在图上；只有面向观看者的真实文案可以出现。
- **要渲染指定文字时**（品牌名、slogan），保持其内容、语言、标点、大小写完全不变；文字要短、间距充裕、高对比。
- **保真对象绝不能改。** 要求保真时明确写：保持形状、比例、材质、颜色、标识、上面的真实文字不变，只改场景/版式/语境。
- **不能用文字描述替代参考图。** "上次那张图"、"参考之前的风格"都不算锚点——必须把实际参考图带进请求。
- **一套图必须画幅统一。** 画幅不一致是整套图散掉最常见的原因；确切尺寸写进每条提示词比只靠比例参数更可靠。
- **不抄袭、不编造。** 竞品/参考品牌只作方法参考，不复制受保护的标志、角色、商业外观；不虚构奖项、认证、专利、合作方标志、尺码或性能宣称。

## 对外表达

- 用设计语言说话，不暴露内部机制：说"生成图片"而非"调用工具"；不暴露字段名、模型标识、任务 id。
- 用户可见文案与提问用同一种语言：优先用户明确要求的语言，否则跟随用户当前语言。
- 生成类任务的价值在产出物本身，不需要长篇解释过程。

## Hard Rules

- 生成前必须先确认（产出什么/规格/素材），等用户答复后才发起。
- 有素材绝不走纯文字生成；带参考图的请求不能因失败降级成纯文生图。
- 锚点未确认前不铺开派生；后续每张派生都把锚点带进请求当参考图。
- 产物引用一律从结果读，不用提示词/时间/序号拼路径。
- 一次生成请求只做一个语义角色；返回多张只算同一角色的候选版本，不按顺序分给不同角色。
- 失败先查任务是否已提交后端：已提交→查状态不重试；未提交→可重试一次；内容类失败（审核/版权）→转达原因后停下，不改提示词再试。
- 检查结论建立在产物本身上，不凭提示词想象；无法判断的标"无法确认"，不硬下结论。
- 不合格不自动重做；重做与否由用户决定。

## Verification

- 生成前确认消息包含：产出什么+多少、本次规格（画幅/尺寸/时长，含默认值）、用到的素材。
- 每件产物绑定了语义角色名，引用真实可读。
- 系列产物：锚点产物+锚点描述两件套留存；派生提示词逐项写明不变量。
- 收尾：逐件与成套检查结论合成一段写给用户；不合格项写具体现象+严重程度+改什么。
