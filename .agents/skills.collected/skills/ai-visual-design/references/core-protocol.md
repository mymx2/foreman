# 核心协议：输入、产物、确认、失败、质量门

所有场景共用的执行协议。生成任何视觉资产前必读。

## 一、生成前确认与费用边界

每次发起生成前必须先确认，等用户答复后再发起。这步要用户点头的不是风格偏好，而是**这次到底要产出什么**。

### 参数怎么定（能不问就不问，只问关键的）

| 参数性质 | 处理 |
|---|---|
| 有合理默认值 | 直接用默认值，不问；但定下来的值要写进确认里展示 |
| 会改变整份产出结构 | 必须明确，不明确就问。这类参数决定后面每一步（品牌范围决定产出 5 项还是 1 项），不许猜 |
| 用户已经说了 | 原样跟随，不要"优化" |

### 确认里要写什么（只做一件也要写全）

- **产出什么、多少个**。会产出多个资产而用户没明确要求这个规模时，把更轻的做法做成并列选项（如用户只说"帮我做品牌设计"，要告知全案是 5+ 张分多批，同时给"只要 Logo"选项）。
- **本次的规格**。画幅、尺寸、时长——包括按默认值定下来的那些。
- **会用到的素材**。用户给的参考图、上一轮的锚点；一个都没用到也要说明是纯文字生成。

规格必须写在确认正文里，不能只放进某个选项的描述（那样等于把规格绑死在那个选项上）。按默认值定的参数照样要展示，用户不反对即生效。真正需要拍板的维度才做成选项；多个维度要拍板时一次问多个，一个维度一个问题。

### 什么时候问

- **一批一次**：开工前对整批问一次，同意后做完，批内不逐张追问。
- **需要重新问**：产出规模超出已确认范围、关键参数实质变化、用户要求重做或改稿、进入此前未确认的下一批。
- 场景手册明确要求逐项定稿时（如品牌锚点），按场景走，不被"整批已同意"覆盖。

## 二、用户附件与参考素材（输入契约）

用户带了附件或参考素材时才需要遵守本节。

- 附件可用路径由宿主提供，拿上下文里已有的引用；**不要猜测或推断文件位置**。
- 场景要求必须有参考图（如电商详情图必须有产品实拍）而上下文没有可用图片时，停下问用户要；**不要用纯文生图代替**。
- 收到的参考素材**全部带进**生成请求，不静默丢弃、抽样或去重。某份素材无法用于当前方式时（如给只接受图片的生成喂了视频），说明排除了它及原因，不要吞掉不提。
- 超数量上限时**不要静默截断**：告知上限，按用户可见顺序保留前 N 个，或问留哪些。静默截断会让用户以为所有素材都生效了。
- 多份素材各有用途时，在提示词里写明每份的角色（"图1主体参考、图2风格参考、图3构图参考"），否则模型不知道从哪张提取什么。

## 三、产物引用（产物契约）

### 一律从结果里读，不预判路径

产物文件名不可预判，必须从生成结果里读实际引用；不要用提示词、时间或序号拼路径。

### 一个语义角色 = 一次生成请求

多步流程里给每个产物起**语义角色名**（主视觉、场景一、细节特写-织纹、尺码图）：

1. 每个语义角色单独发起一次生成请求；不要一次请求多张再按顺序分给不同角色。
2. 结果返回后立刻把实际产物引用绑到该角色上并记下来。
3. **一次请求返回多张图时，它们只是同一角色的多个候选版本**；不许按数组顺序分给不同角色——顺序不保证符合预期，对不上会把整套标错。
4. 后续步骤一律用语义角色名指代；真正发起请求时再解析成实际引用。

### 记账与跨轮次有效性

宿主可能提供会话级产物登记，有就用；没有就自己维护语义角色与实际引用的对应关系，每次用都核对。跨多轮对话继续的流程，每轮开头先确认此前的产物引用仍有效；无效就重新确认或重新生成；不要拿着无效引用继续做。

### 跨轮次风格锚点

用户很少一次做完。更常见：先做一张，再说"再来几张同样风格的"、"换个场景但保持这个感觉"。这种延续必须接得上，否则每轮都在漂。

**风格锚点由两部分组成，缺一不可**：
1. **锚点产物**——用户接受的那张图/那段视频本身，视觉事实的来源。
2. **锚点描述**——当初生成时用的风格描述文本（媒介质感、配色、光线、构图逻辑、主体特征等）。

只记产物不够（纯文生图复用不上）；只记描述不够（文字带不住视觉细节）。两样都留。

- **什么时候立锚点**：用户对某个产出接受、选中、或说"就这个"→立刻连同当时的风格描述记为锚点并绑语义角色名；场景要求先锁基线时（先确认主形象再派生），那张图就是锚点；用户给的参考图被当作基线时，它也是锚点。
- **后续轮次怎么用**：先判断是不是延续（"再来几张"、"换个场景"、"保持这个风格"都是信号，拿不准就问）；确认锚点产物引用仍有效（无效请用户重新提供，**不要凭记忆重述当时的风格**）；把锚点带进新请求——产物作参考图，描述作风格块原样复用，只改这轮要改的；写清哪些保持、哪些改（延续请求最易犯的错是"每样都改了一点"）。
- **用户主动换风格**："换成手绘风"、"整体更冷"→作废旧锚点、按新方向立新锚点，不要一边用旧锚点一边迁就新方向。但要分清"换风格"和"在当前风格里调整"（"颜色再亮一点"、"人物再靠左"是调整，保留锚点）。判断不了就问。
- **本轮压过历史**：历史锚点是参考不是命令，用户这轮说的和历史冲突时跟用户当前要求走。

## 四、失败处理（先问：这次请求送到后端了没有）

出错先分清请求是否已提交。送出去了就不要无脑重试——那是最贵的错误。

### 已提交 → 先查状态，不重试

失败信息里带任务标识，就说明请求已送到后端（提交后超时、轮询中途鉴权失效、网络中断都算）。任务很可能还在跑甚至已做完。绝不因"没拿回结果"就再发一次（那是提交一条全新任务）。先拿标识查后端状态：
- 还在进行 → 如实告诉用户还在生成。
- 已完成 → 按标准验收交付。
- 已失败/已取消/后端不认识 → 才轮到问用户要不要重新生成。

### 未提交 → 可重试一次

没送到后端的瞬时错误可重试一次，绝不循环重试。分不清发没发出去时按"已提交"走（先查，不重试）。

### 内容类失败 → 不重试

内容审核不通过、版权问题这类是内容问题不是偶发故障。把工具给的原因与建议转达用户，然后停下；不要自己改写提示词再试、不要换个模型再试。

### 参数被拒 → 修正后重试一次

尺寸、模型等参数不合法被直接拒绝、请求没进入生成时，按报错修正后重试一次，不必为此打断用户。但修正后的规格与生成前确认展示过的实质不符时（竖版变方形、时长砍半），不能默默换规格交付：要么改回原规格，要么回去重新确认。

### 硬约束不得为"跑通"而牺牲

用户给的参考素材、明确固定的属性、场景合规要求都是硬约束：带参考图的请求不能因失败降级成纯文生图；不能把参考图转写成文字描述替代；不能为凑数用别的东西填充。一次调用失败后报告失败并停下，不要连环换方式硬试。

### 链式流程按阶段失败

多阶段流程某阶段失败时在该阶段停下，不带残缺的中间产物往后做，不把中间产物当最终交付物。

### 一件失败不影响已拿到的几件

一批里第 3 件失败时，前 2 件已生成、已计费。如实说明做成了哪几件、卡在哪一件，让用户决定要不要继续。

## 五、交付验证（质量门）

### 结论必须建立在产物本身上

下判断的依据只能是产物本身：图片要读回来看过再说它长什么样，视频要从返回信息里读实际规格。凭提示词想象产物写结论，等同于伪造检查——提示词写了什么和模型画出了什么是两件事。

### 逐件检查（只做一件也要做）

- 产物可用——引用有效、真能读回来，不是编造的路径或链接。
- 内容对得上诉求——用户点名的核心要素（主体、动作、场景、图上文字）确实出现在画面里。
- 实际规格与确认过的一致——实际用的画幅、尺寸、时长和确认那份对得上；对不上如实说明，不用"大致就是那个比例"糊过去。
- 数量对得上——交付数量与承诺一致，没把失败的算成成功的。
- 文字可读——图上文字清晰、语言一致，没把内部规格（色值、字段名、提示词片段）画进画面。
- 场景硬门禁全过——场景手册自带清单时以其为准。

### 成套检查（产物齐了才做得了）

- 规格统一——画幅逐张核对，任何一张与锁定值不符都要重做。
- 保真对象未被改动——需保真的产品/服装/标识/角色，与原参考逐项对照。
- 一致性成立——同一主体/风格的多个产物，身份特征与风格前后一致。
- 没有重复——一套里不能出现两张几乎一样的；只是换了文字的要重做一张。

### 检查结论怎么给（写进给用户看的回复里）

只在心里过一遍等于没做。一批多件时，逐件与成套结论合成一段写出：
- 不合格项写具体现象——哪个产物、哪一项、具体错在哪（"质量不好"没法行动）。
- 分严重程度——区分「硬门禁不合格，不该交付」与「可接受但有改进空间」。
- 给出改什么——如果要重做，说清具体改哪里。
- 无法判断的如实标"无法确认"，不凭印象下判断。
- 全部合格一句话带过，不逐条复述清单，不为显得尽职挑无关紧要的问题。
- 只核对一次，不反复审形成审查循环。

按严重程度处置：硬门禁不合格→不能宣布交付成功，指名说清哪件哪项，确认是否重做；可接受但有改进空间→算交付，同时如实说明。

**不要自动重做**（重做要花钱），由用户决定。**不得伪造检查或产物**：没生成就不能声称已生成，不编造产物引用、任务状态或进度百分比。
