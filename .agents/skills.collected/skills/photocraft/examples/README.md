# PhotoCraft 案例

每个场景都是可直接运行的 Python 脚本，跑完用 `info`、`type.info`、像素取样和命令返回值核对产出。不带参数时使用内置素材；带参数时处理你自己的文件（原文件只读，产出写到 `$PCX_WORK/out/<场景>/`）。场景数量和通过率以 `scripts/run_examples.py` 的输出为准；案例 31 需要桌面窗口，默认跳过。

```sh
python <skill-dir>/scripts/run_examples.py            # 全部；案例 31 默认 SKIP，设 PCX_DESKTOP=1 才运行
python <skill-dir>/scripts/run_examples.py 03 batch   # 名称含 03 或 batch 的
PCX_WORK=/tmp/pc python <skill-dir>/examples/12-product-cutout-composite.py my-product.jpg my-scene.jpg
```

依赖：Python 3.10+、已安装的 PhotoCraft。核心示例只用标准库；案例 34 需要 `psd-tools` + `Pillow`，案例 35 需要 `Pillow`（`pip install -r scripts/requirements.txt`）。不需要 bash 或 Node。CLI 位置用 `PHOTOCRAFT_CLI` 指定；`PCX_WORK` 改工作目录。

## 两种模式

- **演示模式**（不带文件参数）：输入来自 `assets/` 或现场生成的夹具，质检可以按夹具的已知内容断言。
- **用户模式**（带了文件参数）：只做不依赖夹具几何的质检；只对夹具成立的检查会打印 `skip`（不算失败，也不冒充通过）。

脚本里的用户输入会先转成绝对路径再切工作目录，所以相对路径、`C:\…`、`~/…` 都能用。每次运行会清空自己的输出目录（带 `.pcx-out` 标记）；用户指定的 `PCX_WORK` 下非空且无标记的目录会被拒绝删除，确认可以丢弃后设 `PCX_FORCE_CLEAN=1`。默认临时根目录（未设 `PCX_WORK`）是例外：旧版本留下的非空目录也会直接清空。

## 目录

- `pcx.py`：公共库（定位 CLI、`pcx_init`、`fixture`、`pcx_input`、断言、`info`/`pc_run`/`pcx_ppm`、像素分析 `Img`）
- `assets/`：两张公有领域画作（来源见 `assets/SOURCES.md`）；其余素材由 `fixture` 现场生成
- `actions/`：批处理动作文件；`data/`：变量数据；`clients/`：serve、MCP、桌面控制通道的 Python 客户端

## 写新案例的约定

1. 文件名 `NN-场景.py`，docstring 写清场景、要点和用法。
2. `from pcx import *` 后，用户参数先用 `pcx_input` 转成绝对路径，再 `pcx_init <名字>`；之后都在输出目录里，用相对路径。
3. 文件末尾调用 `run(main)`，异常会统一转成 FAIL 与非零退出码。
4. 输入先复制进输出目录再处理，原文件只读。
5. 每个产出都要有断言：尺寸、模式、图层、像素取样或命令返回值，失败时 `fail` 退出非零。
6. 只对夹具成立的检查用 `if demo_only("…"): …` 包起来，用户模式下会跳过。
7. 需要外部条件（桌面窗口、网络）的场景，条件不满足时调用 `skip("…")`（退出码 77）表示跳过。
