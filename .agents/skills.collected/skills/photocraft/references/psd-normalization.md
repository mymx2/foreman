# PSD 规范化与复刻

把单文件、层树混乱的 PSD 变成可维护的规范稿。验收有两条：渲染一致；结构可读。像素一致不能替代结构验收。

## 目标结构

按需使用下列根组；用到的类别必须按此顺序自上而下排列。未使用的类别可以省略，但要在规范化记录里说明：

| 根组 | 放什么 | 规则 |
| --- | --- | --- |
| `参考` | 原稿平图/截图/对照 | 隐藏、置顶、不参与合成 |
| `调整` | 全局调整层、智能滤镜 | 作用范围明确；局部调整放进目标组并剪辑 |
| `装饰` | 形状、图标、光效、线条 | 保持可编辑；重复元素用智能对象 |
| `文字` | 全部文字层 | 保持文字层，不栅格化 |
| `主体` | 产品、人物、核心视觉 | 抠图用蒙版；复杂合成用智能对象 |
| `背景` | 底色、背景图、渐变 | 置底；不承载主体内容 |

多页面/多版本：根组用 `页面_<名称>` 或 `版本_<名称>` 包装，每个包装组内部再按上述六类分组。同一层不要混用页面包装和裸类别。

## 命名与层树

- 命名用 `类别_语义[_状态]`：`文字_主标题`、`主体_产品抠图`、`装饰_光晕_左`、`背景_渐变`。组名同规则。
- 同一父级下不重名；重名用 `_01`、`_02` 区分。
- 禁止默认名（`图层 1`、`组 2`、`文本 1`、`Layer 1`、`Group 2`、`Copy`、`未命名`）、空名、首尾空格、`副本/拷贝/copy` 后缀。
- 所有内容进组；根层不允许散落图层。空组、单子层冗余组清理掉；有语义保留价值时在描述文件说明。
- 最大嵌套 4 层（页面包装 → 类别 → 子组 → 图层）；超过就合并或扁平化。
- 同一组超过 30 个平级层，按语义再分组（软上限）。
- 隐藏层只允许在 `参考` 或 `版本_*` 下；其他位置的隐藏内容删除，或移入版本组并登记。
- `文字` 组只放文字层。像素层/智能对象出现在文字组，按“可能已栅格化”处理，必须确认。
- 调整层放 `调整`，或放进目标组并剪辑到目标；不要让调整层跨组误伤。
- 抠图用蒙版，不擦像素；复杂合成、重复素材用智能对象；最终平图另存，不把合并结果当母版。
- `参考` 放原稿平图/对照截图并隐藏；原 PSD 不覆盖、不删除。

## 入稿审计

审计脚本依赖 `psd_tools`；缺失时先安装 `psd-tools`。脚本只读，不改 PSD。

1. 原稿只读：先算 SHA256，禁止在原稿上重建或改 `text.font`。
2. 运行 `scripts/psd-audit.py audit <原稿> --json > <稿目录>/audit-before.json`（运行它），记录层数、组数、最大深度、默认/重复名、空组、根层散落、隐藏层、文字层与字体、根分类缺失/顺序。
3. 在 PhotoCraft 打开原稿，`document.inspect` 复核层树/文字/字体；`type.resolveMissingFonts` 拿应用侧的真实缺失清单。脚本读 PSD 字体表，安装状态以应用为准。
4. 先出问题清单和重建计划，再动手。确认后把原稿另存为 `<稿名>_规范.psd`，之后所有重建、字体回写、保存都在规范稿副本上进行；原稿与规范稿的 SHA256 都要记录。原稿是平图/合并层时，明确标注“无法恢复原始层，只能按视觉复刻”。

## 复刻流程

1. **冻结基线**：用同一引擎把原稿渲染成 PNG（headless `photocraft-cli convert` 或 `doc.render`），保存并记 hash；后续所有视觉对比以它为基线。
2. **设计目标层树**：按目标结构写旧层→新组映射；标出要拆的合并层、要重打的文字、要转智能对象的素材、无法恢复的项。
3. **另存规范稿**：在 PhotoCraft 用 `app.save {path: "<稿目录>/<稿名>_规范.psd"}` 另存，确认当前文档已指向规范稿；不要用无 path 的 `app.save` 回写原稿。记录原稿与规范稿 SHA256。
4. **在副本上重建**：建组、改名、移动层、转智能对象、补蒙版/调整层；每批改动后 `document.inspect` 复核。保留原稿与 `参考` 组。
5. **补字体并回写**：`type.resolveMissingFonts` → 候选（`scripts/fonts/zitijia-free.py` / `hellofont-search.py`）→ 用户确认 → 安装/注册 → 在规范稿上写 `text.font` → `type.fonts` 复核。禁用 `type.replaceAllMissingFonts`；缺字体未确认前不交付，不静默换近似字体。
6. **文字规范化**：文字保持可编辑；逐层核对 family/style/字号/字距/行距/颜色/对齐/边界；记录替换字体的理由和视觉差。
7. **视觉验收**：`python scripts/psd-compare.py <原稿渲染> <规范稿渲染> --out <稿目录>/psd-compare-out > <稿目录>/visual-diff.json`（同引擎，默认 fuzz 0）。目标 `identical`；有差异逐像素定位并修复。跨工具来源才给 `--fuzz`，并写明原因。另做 fit/100% 双尺度目检。
8. **结构验收**：`python scripts/psd-audit.py audit <规范稿> --strict --json > <稿目录>/audit-after.json`；`--strict` 要求无 CRITICAL/HIGH/MEDIUM，LOW 逐条解释；再跑 `compare <原稿> <规范稿> --strict` 记录前后指标。
9. **交付**：按 `references/delivery.md` 输出母版、描述文件、`fonts/`（授权允许时）、审计前后 JSON、视觉对比 JSON、规范化记录。原稿与规范稿分开保存，不覆盖。

## 验收

- **视觉**：`psd-compare.py` 报 `identical`；或差异已定位、解释并经用户接受。fit 看构图色彩，100% 看文字边缘与伪影。
- **结构**：`psd-audit.py --strict` 无 CRITICAL/HIGH/MEDIUM；根组分类与顺序正确，未使用的类别已说明；无默认/重复名、空组、根层散落、隐藏垃圾；文字可编辑。
- **字体**：`type.resolveMissingFonts` 无缺失，`type.fonts` 能看到目标字体；审计脚本的字体清单不是安装证明，不能用它替代应用侧检查。
- **文档**：`delivery.md` 模板完整；规范化记录含原稿 hash、审计前后摘要、旧层→新组映射、字体替换、视觉对比、未解决项。
- **可复跑**：审计、视觉对比、字体核对命令都能在原稿/规范稿上重跑。

## 例外处理

- **平图/合并层**：无法恢复原始层；按视觉复刻，规范稿结构是新建的，描述文件注明“复刻自平图”。
- **栅格化文字**：优先重打；不能重打时放 `主体` 或 `装饰` 并在描述文件注明，不留在 `文字` 组。
- **合并主体/素材**：有源文件就拆；没有就作为智能对象放进语义组，注明来源缺失。
- **缺精确字体**：出候选让用户定；替换后记录 family/style、授权和视觉差；不自动用近似字体。
- **不支持的智能滤镜/效果**：在副本上烘焙，把原效果隐藏副本放进 `参考`，描述文件注明不可回改。
- **多页面/多版本**：用 `页面_*`/`版本_*` 包装，内部仍按六类分组；不要把多页平铺成一层。

审计输出的根组顺序为面板自上而下；`psd_tools` 内部层列表是自下而上，报告已转换。规范化验收用 `--strict`：MEDIUM 也视为失败；LOW 可解释后放行。默认模式只把 CRITICAL/HIGH 当失败，适合日常巡检。

## 审计严重度

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| CRITICAL | 无法安全交付/结构不可用 | 打不开、无层、文字全部缺失 |
| HIGH | 必须修 | 默认名、同级重名、空组、根层散落、文字缺字体、文字组内像素层 |
| MEDIUM | 应修/需说明 | 根分类缺失或顺序错、深度超限、隐藏层乱放、文字不在文字组、复制名 |
| LOW | 建议 | 单子层组、同级过多、可疑栅格化文字 |

## 规范化记录

写入 `<稿名>.md` 的「规范化记录」一节：

| 项 | 值 |
| --- | --- |
| 原稿 | 文件名 + SHA256 |
| 原稿审计 | audit-before.json 摘要（层/组/深度/HIGH 数） |
| 规范稿 | 文件名 + SHA256 |
| 规范稿审计 | audit-after.json 摘要 |
| 分组/命名 | 本文约定 + 例外 |
| 旧层→新组 | 映射表或映射文件 |
| 字体替换 | 原字体 → 实际字体、理由、授权 |
| 视觉对比 | psd-compare 结果、diff 图、fuzz/原因 |
| 未解决项 | 无法恢复的层、已知差异、用户待决 |
