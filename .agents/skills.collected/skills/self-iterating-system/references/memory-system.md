# 四层记忆系统 Schema

实验回收得到的经验需要合理保存，也要在合适的任务里取得出来。四层记忆把不同性质的信息放进不同成本、容量和检索方式的容器，让相关信息在需要时进入模型上下文。

## 分层结构

| 分层 | 承载内容 | 典型内容 | 消费方式 |
| ---- | ---- | ---- | ---- |
| 核心规则 | 稳定、高频、每次必须生效的规则；由人工审核的确定性内容 | 唯一核心指标、行动边界、诚实纪律、数据口径红线 | 常驻注入 |
| 知识 | 已沉淀的经验与教训；LLM 可检索、自演化 | 已验证规律（按现象/机制/未验证推断分级）、成败经验（含条件、限制、证据和反证）、程序性方法 | 按产品类型与任务需求动态匹配，引用时携带匹配分数 |
| 历史记忆 | 原始事件与证据；LLM 提炼的历史摘要 | 分析轮次、运营动作变更日志、内部改动迭代记录、迭代与 AB 实验时间线 | 原始事件：唯一可直接引用的历史证据；历史摘要：只作背景补充 |
| 会话记忆 | 会话中的所有内容 | 会话详情、SDK 转录信息、本轮任务状态 | 中断重连：恢复会话的必要消息 |

## 记忆正文格式

一条记忆的正文只保留「结论 + 判断依据」。不保存一次性细节和容易过期的时效数值。

```
结论：{一句话可执行的判断}
判断依据：{支撑该结论的证据链，引用历史记忆中的原始事件 ID}
```

## 治理元数据

每条记忆必须携带五个治理字段：

| 字段 | 取值 | 说明 |
| ---- | ---- | ---- |
| 作用域 scope | 单个产品 / 跨产品复用 | 决定检索时的匹配范围 |
| 来源证据 source | 结算 ID、会话 ID | 可回溯到具体哪次对账、哪个会话 |
| 证据等级 evidence_level | 现象 / 机制 / 未验证推断 | 低等级内容禁止使用"显著""必然"等强断言。机制等级需实验数据支撑；无实验平台的环境上限为现象 |
| 置信度与状态 status | 候选 / 生效 / 已失效 | 新记忆先进候选，对账验证产生支持证据后连同证据提交人工评审，评审通过转生效；被证伪转失效但不删除 |
| 版本链 version | 生成该记忆时的系统状态指针 | 可回溯当时的数据口径、代码版本、知识库快照 |

## 冲突优先级

同一会话中多层记忆同时进入上下文时，冲突按此裁决：

**核心规则 > 历史记忆中的原始事件 > 生效知识 > 候选知识 > 历史摘要。**

例：生效知识说"该品类奖励系数应 >1.2"，核心规则口径红线说"系数上限 1.0"——核心规则赢，且该知识进入复核流程。优先级不可被知识自身覆盖；能改核心规则的只有人。

## 读出规则：暂存区与分层

- pending 暂存区条目**可被读出，但注入时必须带"未验证"标记**，且禁止作为方案的唯一依据——它服务于"读出宽"的探索，评审转正前不享受生效知识的权重。
- 生效知识按作用域与匹配分动态注入，引用时携带匹配分数。
- 匹配分数 = 作用域吻合度 × 任务类型吻合度 × 证据等级权重；阈值由系统设计时显式设定，低于阈值不注入。

## 晋升与失效的裁判

- 候选 → 生效：**人工评审**（暂存区转正）。对账验证产生的支持证据作为评审材料一并呈现，不自动晋升。
- 生效 → 已失效：实验对账证伪（机器可判定，到期自动结算触发）或人工评审驳回。
- 已失效不删除，保留版本链供审计。

## 级联失效

知识之间通过「引用关系」成链（每条知识的"来源证据"记录它引用了哪些知识条目）。一条生效知识被证伪时：

1. 沿引用链正向找出所有引用过它的知识，全部降级处理：证据等级降一级，状态转候选，重新进入评审。
2. 级联操作本身作为一条变更记录写入历史记忆（谁被证伪、波及哪些条目、何时发生）。
3. 核心指标变更时，触发批量复核：所有证伪条件依赖旧指标的"生效"知识批量转候选，重对账后再决定恢复或失效。

## 自演化规则

1. 实验到期对账时，逐条追溯本次判断引用的知识。
2. 知识被验证 → 支持证据记入条目，作为人工晋升评审的材料。
3. 知识被证伪 → 状态转已失效并触发级联失效；证伪结论本身成为一条新知识（先进候选）。
4. 引用时按作用域和任务需求动态匹配，携带匹配分数进入上下文；匹配分数低的知识不注入。

## 读写链路：写进严，读出宽

### 读出（正确的记忆在正确的时间进上下文）

- 任务手册强制拼装：按任务把必读条目原文直接注入，附步骤、门禁、已知死路。
- 按需检索兜底：目录 → 定位 → 全文。

### 写入（所有修改先过暂存区）

- Agent Team 产出的记忆只写「结论 + 判断依据」，不写一次性细节与时效数值。
- 实验结算 / 迭代效果归因写回版本时间线记忆。
- 所有增 / 改 / 删一律进 pending 暂存区（类似 git staging，打待评审标记）：人工评审通过 = 转正写入领域知识库；驳回 = 反向恢复。暂存区条目可被读出，但注入时带"未验证"标记且禁止作为方案唯一依据（见「读出规则」）。
- 人对分析产出的日常反馈由专职 Agent 读取，提议知识修订，同样过暂存区。
- 经验卡（成功 / 失败策略 + 适用边界，预期收益用历史实测锚定）可经高置信晋升进入核心经验层。
