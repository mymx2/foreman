# 美术资产生产线

美术资产最难的不是"能不能生成图片"，而是生成结果能否稳定进入工程。本文件是 SKILL.md Process 第 3、4 步的完整执行契约。

## 输入

- GDD 策划方案（资产需求清单、视觉风格定义）。
- 调研阶段选定的风格参考图。
- 可选：音效设计参考。

## 执行模式（四种，按需路由）

1. 全量生成：首次或全部重做。
2. 局部重生：指定资产重新生成——不从头跑整条线。
3. 续生：完成 pending/error 资产。
4. 咨询：美术方案问答，不产生资产。

## 资产规划（两阶段拆分，职责分离）

- 阶段一 工程视角分析：游戏类型 + GDD → 视角推导（横版/俯视/正面决定朝向）；分析代码消费模式（直接使用 / 无缝平铺 / 可延伸拼接 / 网格单元 / 程序绘制）决定资产怎么拆；输出技术约束：朝向、画风参考、实体参考、宽高比、描述。
- 阶段二 视觉设计：只聚焦"怎么画"，逐资产撰写视觉描述：画风 / 色彩 / 材质 / 形态。
- 产出：完整资产清单（含朝向图、拆分图、依赖关系）→ 进入生成。

## 生成执行

1. 依赖分析定序：从 GDD 提取风格描述与资产清单，构建依赖图；无依赖资产并发，有依赖的等依赖完成后级联启动。
2. 分组生成（组内顺序、组间并发）：每张图生成后抠图（智能 matting + 分割）。
3. 三级一致性锚点：
   - 基准风格 Base：调研阶段选定的风格参考图。
   - 整体风格 Style：首张生成的素材作为锚点，后续资产以此为参考。
   - 代表图 Entity：有多种状态/关系的游戏对象，用标准态作为参考。
4. 资产依赖图：维护"谁参考谁"的链，新增资产必须显式指定参考对象。
5. 页面框架图：所有元素完成后合成完整页面视觉稿，分析游戏区布局，输出结构化布局描述——编码环节读到的是布局意图，而不是一组零散图片和文字。
6. 资产交付：美术资产分组 + 音频资产清单，进入编码环节的可用上下文。

## 资产矫正

生图无法精准对齐的问题（尺寸、朝向、拼接边）用工程能力处理：程序裁切、网格对齐、程序绘制兜底，不反复赌生成。

## 音频生产线

- 从 GDD 梳理需要声音反馈的场景，自主规划音频清单（名称、描述、时长、分类），灵活应对不同游戏类型。
- 逐个创建生成任务、轮询结果、试听校验；失败任务重试。
- 产出四类：BGM 背景音乐、交互音效（点击/拖拽/操作反馈）、状态音效（成功/失败/奖励）、UI 音效。编码环节按场景直接引用。
