# 案例：从零固化为可交付脚本

一个完整走通的例子，演示方法论怎么落地。**所有应用名、字段名、编号、路径都是占位值**——案例给的是步骤和判断方式，不是某个应用的配方。

## 需求形态

> 打开某个桌面应用 → 导航到「审批 → 历史记录」→ 按完成时间区间查询 → 打开详情 → 下载 PDF → 另存为到指定目录；然后按编号查另一条，重复下载。

特征：多步导航 + 表单筛选 + 列表操作 + 浮层 + 系统对话框 + 文件产物。是典型的「GUI 固化」场景。

## 第一步：先看清环境

不要打开应用就开始写定位器。先回答四个问题：

```
scene.py --title "<窗口标题>"
```

输出会直接告诉你：

- 有几块屏、各是什么缩放
- 目标窗口的**逻辑尺寸**（不是物理尺寸）——这决定界面是完整布局还是紧凑布局
- 是否在前台、有没有被别的窗口压住
- 有没有残留的对话框或浮层

这个案例里就是这一步发现了关键约束：窗口逻辑尺寸只有 960×516，大量控件被压到十几像素，部分按钮直接挤出可视区。**如果跳过这一步，后面所有"找不到元素"都会被误判成定位算法的问题，去改一堆不相干的东西。**

## 第二步：拆成段落，逐段验证

不要写完整个脚本再跑。按段拆，每段单独验证通过后再接下一段：

| 段 | 验证什么 | 怎么验证 |
|---|---|---|
| 启动 | 能找到 exe、能等到窗口、句柄稳定 | 打印 pid + 句柄，确认句柄不再变化 |
| 导航 | 三个层级都能点到 | 每点一次就 `observe` 确认页面换了 |
| 筛选 | 日期/文本能填进去且**保持** | 填完再读一次，确认值还在 |
| 查询 | 结果集**数量正确** | 数一数「查看」按钮有几个 |
| 详情 | 打开的是**目标那条** | 从详情里读编号与目标比对 |
| 下载 | 对话框弹出来 | 检测新出现的顶层窗口 |
| 保存 | 文件真的落盘且内容正确 | 读文件头 + 解析内容核对主键 |

每段都控制在秒级。**全流程只在最后跑，用来验收组合是否成立，不用来调试。**

## 第三步：踩到的坑（按发现顺序）

这些坑不特定于某个应用，同类界面上都可能遇到：

**1. 抓图内容不全**

第一版用 `PrintWindow` 抓窗口，OCR 只读到一半控件，导致「查询按钮不存在」这类误判。换成屏幕裁剪后一切正常。

教训：**抓图优先用系统截图**。某些 GUI 框架下 `PrintWindow` 会返回尺寸正确但只合成了一部分内容的位图，而且不报错。

**2. 坐标整体偏移一倍**

修好抓图后点击仍然无效。逐点比对发现：截图坐标是物理像素，但代码又按 DPI 缩放除了一次。

教训：**同一份数据只能换算一次**。抓图来源不同（屏幕裁剪 vs PrintWindow），坐标系就不同，必须按来源决定要不要缩放。

**3. 点击被前台窗口吃掉**

坐标对、窗口对、光标位置对，就是没反应。查前台发现目标应用不在最前。

教训：`SetForegroundWindow` 在后台进程调用时会被系统拒绝，必须用 `AttachThreadInput` 附加到前台线程再调用。`WindowFromPoint` 报告"光标下面是目标窗口"不代表点击能被它接收。

**4. 浮层是独立窗口**

详情抽屉、下拉面板、系统对话框都不在主窗口里。按主窗口的进程 ID 过滤会漏掉它们——特别是系统对话框，常常由另一个进程托管。

教训：**按 `GW_OWNER` 跨进程枚举**，动作前后对浮层句柄做差集。

**5. 关闭按钮位置随窗口尺寸变**

硬编码「右上角内缩 48px」在一种尺寸下能用，换尺寸就点不中。

教训：**用 OCR 找 × 字形**，或者按内容锚点推算，不要写死边距。

**6. 查询结果延迟刷新**

点查询后立刻操作，用的是旧列表——打开并下载了**错误的记录**。

教训：查询后**等结果集数量稳定**再动。因为数量变化能反映状态，比单纯等待可靠。

**7. 输入未提交**

填了文本但查询没生效，因为值还在未提交状态。

教训：填完**回读确认值出现**再进入下一步。

**8. 按钮文字 OCR 读不出**

某些按钮是色块白字，OCR 返回空。但按钮确实存在。

教训：找按钮时可以**借用邻居做锚点**（比如「重置」右侧固定偏移就是「查询」），比直接用文本定位更稳。

## 第四步：稳定性的三条底线

**断点续跑**：每处理完一条就往结果 CSV 追加一行。重跑时跳过已完成的行。这样中途失败不用从头再来。

**产物内容校验**：不能只看文件名。解析文件内容，确认里面包含这条记录的业务主键。列表有多条相似记录时，"文件名对了但内容是另一条"是最容易发生的静默错误。

**失败按行隔离**：一条失败不影响后续。记录失败原因后继续下一条，最后汇总报告。

## 第五步：两份屏幕都要验

同一个应用在不同显示器上可能完全不同的布局——逻辑尺寸差一倍，控件就被压缩到不可用。交付前在**目标使用者实际会用的屏幕**上跑一遍。

如果使用者固定在副屏用，就在副屏验；脚本不要为了"布局更完整"擅自把窗口挪到主屏。

## 交付物清单

- 主脚本：读输入 CSV、逐行处理、写结果 CSV
- 输入模板：一行一条记录，只放业务主键
- 使用说明：怎么跑、参数含义、失败怎么重试、对屏幕/分辨率的要求
- 验收记录：每段验证的日志摘要 + 产物校验结果

**给非技术使用者的版本**要附启动脚本（`.bat` / `.command` / `.sh`），并写明「运行时不要动鼠标键盘」。
